Quality decision safeguards

The database review function enforces these conditions at decision time. The page does not treat a visible file record as proof that the underlying file passed server validation.

01
Completed source task
Only completed goods-receipt or damage-exception tasks can enter the review action.
02
Independent reviewer
The reviewer must differ from the task creator and completer, and must not approve their own inspection evidence.
03
Private inspection report
The server verifies uploader ownership, private evidence bucket, path structure, file type and size.
04
SKU and lot match
The selected inventory record must match the completed source task’s organisation, facility, SKU and lot.
05
One final decision
Release, hold or reject is recorded with an audit event; a second decision on the same task is blocked.

Decision control availability

The current staging database grants EXECUTE on krim_warehouse_review_inventory_quality only to postgres and service_role. It is not granted to authenticated. This browser page therefore cannot safely submit a review decision.

No permission has been widened and no service-role key is exposed to the browser. Release / hold / reject controls remain unavailable until a properly authenticated server-side action is implemented and tested.
