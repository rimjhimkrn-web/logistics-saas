Evidence lifecycle

The target workflow for warehouse evidence, subject to secure backend implementation.

01
Capture against a real task.
Choose a valid receiving, inspection, damage, picking or dispatch task; verify organisation and facility access on the server.
02
Validate and store privately.
Allow only approved file types and bounded file sizes. Store under a server-controlled organisation / user / task path.
03
Record immutable metadata.
Persist evidence type, description, captured time, task, facility, uploader and storage object reference with an audit event.
04
Review with least privilege.
Issue short-lived signed access only after organisation, facility, task and reviewer permissions are checked. Preserve uploader/reviewer separation.

Backend readiness gates

1
Evidence metadata access

Provide a narrowly scoped authenticated read path or server-side function; retain organisation membership and approved-facility checks.

2
Dedicated private storage

Create a warehouse evidence bucket with path-bound upload and read policies. Do not repurpose the partner verification bucket.

3
Task validation

Validate task ownership, task state, facility scope, MIME type, file size and idempotency before accepting an upload.

4
Audit and review

Record upload, access and disposition events; enforce independent review where evidence supports quality decisions.
