Inter-facility transfers

The database contains controlled transfer dispatch and receipt procedures. Transfer dispatch deducts source stock atomically; destination receipt creates or updates inventory on quality hold. A different authorised operator must receive the transfer.

Transfer actions are intentionally disabled in this staging page. The existing dispatch, receive and transfer-quality RPCs are currently executable only by postgres and service_role, not by authenticated users. No service-role key is exposed in the browser, and no permission has been widened to make the buttons work.

Returns & reverse logistics

A return should be linked to its originating shipment and item, inspected at receipt, placed on quality hold where required, and released only after an independent decision.

01
Return authorisation
Capture original shipment, return reason, item, quantity and approved return reference.
02
Physical return receipt
Confirm receiving facility, condition, seal and evidence without silently adding saleable stock.
03
Inspection & disposition
Keep returned stock held until a second authorised reviewer records evidence and a final decision.
04
Restock, repair or reject
Record the resulting disposition and audit event; do not merge inventory with a different quality state.
The current staging database has no dedicated customer-return authorisation / reverse-logistics intake RPC. This return workflow is therefore a design reference only; no return request, receipt or stock update can be submitted here.

Quality & custody safeguards

✓
Only released stock can leave a source facility. Server-side transfer procedure checks the exact source inventory row and available quantity.
✓
Both facilities must be active and approved. The authenticated operator must have access to both facilities for dispatch.
✓
Receipt is independent. The receiving operator must differ from the dispatcher; destination stock is initially held.
✓
Quality release requires evidence and an independent reviewer. Existing review RPC is not granted to authenticated users yet.
