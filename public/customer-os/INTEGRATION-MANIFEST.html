KRIM Customer OS integration manifest

Shared navigation and session bridge. Transactional actions must call the canonical Supabase RPC/Edge Function for each domain; do not write directly to protected tables from the browser.

  • Identity: Supabase Auth session
  • Authorization: existing organization membership, role checks, and RLS
  • Shipment lifecycle: krim_create_global_shipment and krim_transition_shipment
  • Quotes: krim_create_global_quote and krim_accept_global_quote
  • Payments: Razorpay order Edge Function, verified webhook, and payment result page
  • Finance: revenue_ledger and server-authorized settlement flow
  • Tracking/documents/support: use existing canonical tables and RPCs only after schema and policies are verified

This manifest is an integration plan, not proof that all transactions are live.
